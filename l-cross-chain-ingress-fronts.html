WHY THIS DEMO

L · Cross-Chain Ingress Fronts

Builders coming from message-passing bridges tend to picture a cross-chain call as "just hit the RPC." In eez-rollup0 there are exactly two doors a real cross-chain transaction can walk through — an L1→L2 front and an L2→L1 front — and both are narrow: they hold one method, forward everything else, and only resolve once a composer bundles the tx into the next Sync block. This demo walks through what those two proxies actually do, port by port.

What you should walk away understanding
  • A front is a transparent proxy, not a mempool: only eth_sendRawTransaction is intercepted and held; every other eth_* is forwarded verbatim to that front's own source-chain RPC.
  • Direction is fixed by which port you hit, not by the tx's own chain id — the L1 front is always Inbound, the L2 front is always Outbound — and a held tx only resolves when the composer drains it into the next Sync block's bundle.
  • These fronts exist only in composer mode. Follower and standalone nodes never open either port, and EEZ_MAX_USER_TXS_PER_BUNDLE (default 3) is a real cap worth checking against your builder before raising it.

both ports stay closed — no front ever binds
Both cross-chain fronts are spawned inside the same block that also spawns the Sequencer and the Composer umbrella — reachable only when Mode::Composer holds. A follower has no Sequencer; standalone has neither L1 nor a Composer. Neither mode's startup path ever reaches that block, so run_cross_chain_front is never called and EEZ_L1_XCHAIN_PORT / EEZ_L2_XCHAIN_PORT simply go unused.
EEZ_MAX_USER_TXS_PER_BUNDLE · default 3
rbuilder-chiado, not this repo
⦸
beyond ~3, the excess is silently dropped
In code the cap is a re-queue blast-radius control, not a protocol limit — overflow just drains over later Sync slots (pool.pop_n(max_user_txs)). The sharper trap is operational: the README documents that rbuilder-chiado, the external block builder the chiado stack submits bundles to, drops txs beyond roughly 3 instead of erroring — lost tx inclusion, no revert to see. That drop path lives in rbuilder itself, outside this repo, so it's reported here as the README's documented behavior, not verified against rbuilder's own source. Raise the cap only against a builder proven to include larger bundles atomically.
