Deploy on the EEZ testnet

One contract, live on the EEZ L2, in about fifteen minutes. Everything you need is on this page — the walkthroughs explain why it works, and none of them are prerequisites.

Public endpoints are not live yet. Every command on this page is final; the network table fills in the day they are. Meanwhile the same protocol runs on your own machine — run the three dapp steps locally.

[ 00 · BEFORE THE CLOCK STARTS ]

Two prerequisites, then two exports

Foundry v1.7.1 and a funded key. The faucet hands out xDAI on Chiado, which funds both layers.

curl -L https://foundry.paradigm.xyz | bash && foundryup

export EEZ_RPC=COMING SOON   # the EEZ L2 RPC from the table below
export KEY=0x…               # your funded private key

⚠ Use a throwaway key. Never a key that holds real assets — testnet or not.

[ 01 · THE NETWORK ]

CHAINRPC URLCHAIN IDEEZ MANAGEREXPLORER
EEZ L2 (testnet) COMING SOON COMING SOON 0x4200…0007 COMING SOON
Chiado (L1) https://rpc.chiadochain.net 10200 COMING SOON gnosis-chiado.blockscout.com

The L2 manager is a predeploy — the same 0x4200…0007 address on every EEZ L2, known before the network is. The L1 manager address comes from the canonical protocol deploy.

[ 02 · DEPLOY ]

One command

forge create src/MyContract.sol:MyContract --rpc-url $EEZ_RPC --private-key $KEY

Expected output — if you see the last line, you're done:

Deployer: 0x…
Deployed to: 0x…
Transaction hash: 0x…

Verify it landed: cast code <address> --rpc-url $EEZ_RPC — non-empty bytes means deployed.

[ 03 · IF IT FAILS ]

insufficient funds

The key isn't funded on the L2 — go back to the faucet, then cast balance $ADDR --rpc-url $EEZ_RPC to confirm before retrying.

connection refused / timeout

$EEZ_RPC doesn't match the table above — re-copy it. cast chain-id --rpc-url $EEZ_RPC should print the chain id from the table.

nonce too low

An earlier transaction from this key is stuck or already mined — cast nonce $ADDR --rpc-url $EEZ_RPC to inspect, then resend.
