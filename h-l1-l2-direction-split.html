WHY THIS DEMO

H · The L1 ↔ L2 Direction Split

A lot of the API asymmetry between EEZ's L1 and L2 contracts only makes sense once you see why the split exists. This demo draws the line between what each side is responsible for.

What you should walk away understanding
  • L1 owns proofs, the registry, and permissionless draining of the execution queue.
  • L2 is system-gated — only a trusted system address can drive execution — and self-relative.
  • Which entry point runs depends on where the trigger originates, not which chain you're "on."
