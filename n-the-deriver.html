WHY THIS DEMO

N · The Deriver

A rollup is only as trustworthy as its escape hatch. In eez-rollup0, that escape hatch is the deriver: a component that watches L1 for BatchPosted events and re-runs the exact transactions those batches carry, arriving at the same L2 chain the sequencer produced — without ever asking the sequencer for anything. This demo walks through why that single event is enough.

What you should walk away understanding
  • BatchPosted is a thin signal on L1 — the real transaction data lives in the calldata of the L1 tx that emitted it, not in the event's own fields.
  • Re-derivation is deterministic replay: same parent state + same raw txs + same block time convention → byte-identical blocks, every time.
  • "Follower" is a real node mode in eez-node — L1 present, no attestation key — distinct from the eez-driver crate, which is the low-level engine-API block-committer both the sequencer and the deriver drive.
