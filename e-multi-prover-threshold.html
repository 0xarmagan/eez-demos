WHY THIS DEMO

E · Multi-Prover Threshold

How much proof security a rollup wants isn't fixed by the protocol — it's a dial the rollup's own manager owner sets. This demo makes that configurability, and its extremes, visible.

What you should walk away understanding
  • Threshold (M-of-N proof systems) is set per-rollup, not protocol-wide.
  • Threshold 0 disables the proof floor entirely; above N locks the rollup permanently.
  • What ships today is a single-signer ECDSA validator, not a ZK verifier — treat as dev-grade.

A rollup can mix families: a ZK verifier alongside a validator multisig. With M ≥ 2, one compromised prover cannot push an invalid state — the others must still agree before a batch settles.
Reality check: the reference prover shipping today is a single-signer ECDSA validator, not a ZK verifier. No production ZK verifier is live yet.
MYTH
EEZ requires ≥ 2 provers
FALSE
A rollup can set M = 1 — a single prover as its entire trust root — or even M = 0, which sets no proof floor at all. Nothing in the zone forbids it. Multi-prover is a capability, never a floor.
BEFORE YOU BUILD
Read the rollup's actual accepted-systems list and its threshold M. The number of provers is the rollup's sovereign choice, not the zone's.
