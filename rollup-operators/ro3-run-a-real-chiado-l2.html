ROLLUP OPERATORS

How to run against a real testnet

This points the same stack at Chiado instead of a sandbox, from published Docker images.

Configure .env and prepare the embedded L1’s chain data once, deploy once, then one script starts the node, signer and Lighthouse and checks that settlement works.

WHAT YOU'LL LEARN
  • 01 · CONFIGURE ONCE.env from the Chiado example with the RPC, poster and proof-signer keys, plus the L1 snapshot and JWT the embedded L1 needs to sync.
  • 02 · DEPLOY ONCEThe published deploy image writes deployments.env and the genesis files. It broadcasts transactions, so it is never a restart step.
  • 03 · START AND CHECKchiado-up.sh starts the three containers and reports UP only after L2 production, an L1 settlement and retrievable blobs.

PIN YOUR IMAGES · the three EEZ images default to :latest, which can change on startup — set a full Git commit tag or digest for a fixed deployment. EEZ_DEPLOY_SKIP_SIMULATION=1 bypasses Foundry’s pre-broadcast simulation when public RPCs cannot serve its sampled block; broadcasting still occurs. scripts/chiado-up.sh never deploys.

Verified against eez-rollupX @ 2c19e36 — pre-mainnet; interfaces may move.
