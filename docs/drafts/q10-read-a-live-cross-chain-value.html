ONE COMMAND · NOTHING TO INSTALL BUT cast
No Kurtosis, no Docker, no node. These contracts are already deployed on Chiado and the answer is already proven and on-chain. You are reading it.
cast call $READER \ "readUint(address,bytes)(uint256)" \ $PROXY $(cast calldata "getValue()") \ --rpc-url https://rpc.chiadochain.net
123
That number was produced on another chain, proven, and written to Chiado before you ran the command. Nothing fetched it while you waited.

WHY IT ANSWERS WITH NOTHING RUNNING
The read does not travel anywhere. A StaticExecutionEntry holding the answer was posted to Chiado in one batch and sits in that rollup's queue. Your call matches it by hash and returns the value.
staticEntryQueue[rid] ↳ proxyEntryHash == keccak(your call) ↳ destinationRollupId == the proxy's rollup ↳ every pinned state root still live → return returnData
AND WHY IT HAS TO GO THROUGH $READER
Calling the proxy directly does not work. cast call is an eth_call, which the EVM runs as a non-static frame; the proxy probes for static context with a tstore that succeeds there, so it routes to the mutating path and reverts ExecutionNotInCurrentBlock. A Solidity view call compiles to a real STATICCALL, which is the whole job $READER does.

WHAT THIS IS, EXACTLY · AND WHEN IT STOPS
THE ROLLUP BEHIND THIS READ IS INTENTIONALLY PAUSED
This is a real cross-chain read resolving against a real proven entry — and the state it reads is frozen. A queued static entry is deleted the moment any later batch verifies that rollup (EEZ.sol:745 wipes the queue on every verify, roots untouched or not), so a permanently-answering playground is one where nothing is posting. That is the trade: a command that works forever, over a chain that is still moving.
Which runs opposite to intuition. A composer running against this rollup would destroy the entry every block, not sustain it.
WHEN THE COMMAND FAILS
ExecutionNotInCurrentBlock
You called the proxy, not $READER. Route through the helper.
ExecutionNotFound
No entry matched: the calldata differs from the seeded one, a pinned root moved, or a later batch wiped the queue. Not distinguishable from the destination reverting.
UnauthorizedProxy
The address in $PROXY is not a registered CrossChainProxy. Check the table in step 1.

DAPP DEVELOPERS · 09

Read a live cross-chain value

Every other way of seeing EEZ work starts with standing up a devnet. That is a fair ask of someone who has decided to build, and an excessive one for someone deciding whether to.

So: contracts already deployed, one command, a value that came from another chain. If you have cast installed you are about ten minutes from it, and you will not install anything else.
